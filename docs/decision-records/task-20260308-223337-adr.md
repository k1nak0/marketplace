# ADR: task-20260308-223337 — Dev-Workflow Plugin Documentation & Orchestrator UX

**Date:** 2026-03-08
**Status:** Accepted

---

## Context

The `dev-workflow` plugin had no documentation in `CLAUDE.md`, making it invisible
to AI agents that use `CLAUDE.md` as session context. The orchestrator `SKILL.md`
also lacked consistent use of `AskUserQuestion` at interaction points, meaning agents
could silently stall or use plain-text prompts that aren't machine-parseable.

Two additional pain points were identified:
- After a major-rework cycle (Phase b-8), there was no mechanism for a new Claude Code
  session to resume the workflow — state was only partially recoverable.
- All references to `claude-opus` were costly; `claude-sonnet` is sufficient for all phases.

---

## Decision

1. **Create `CLAUDE.md`** at the repo root with a `## Dev-Workflow Plugin` section
   covering: 9-phase workflow overview, annotated file/directory structure, and
   `status.json` / `.claude-status.json` schema documentation.

2. **Replace all plain-text prompts with `AskUserQuestion`** at four orchestrator
   interaction points: startup resume decision, Phase 7 review gate, Phase 7
   minor-fix feedback, Phase 7 major-rework feedback.

3. **Add explicit auto-proceed log statements** at every phase transition that does
   not require user input, so agents never silently stall.

4. **Add a resume-command print block** after Phase b-8 completes: the orchestrator
   prints a copyable `/dev-workflow:orchestrator` command. On re-invocation, the
   workflow reads `.claude/.claude-status.json` and auto-resumes from
   `current_phase: "phase-4-restart"`.

5. **Replace all `opus` references with `sonnet`** across `SKILL.md`, `CLAUDE.md`,
   `agents/implementation-architect.md`, and `README.md`.

---

## Consequences

- **Positive:** AI agents reading `CLAUDE.md` now have full context about the plugin
  without needing to read raw SKILL.md files.
- **Positive:** `AskUserQuestion` calls produce structured, machine-parseable responses,
  eliminating silent stalls.
- **Positive:** Session handoff after major rework is explicit and copy-pasteable.
- **Positive:** Using `sonnet` for all phases reduces token cost.
- **Trade-off:** The `implementation-architect` phase no longer uses `opus`; if plan
  quality degrades for complex tasks, reverting to `opus` for Phase 4 is a one-line
  change.

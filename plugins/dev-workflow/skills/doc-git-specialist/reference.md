# Doc & Git Specialist — Extended Reference

## Documentation File Conventions

### CLAUDE.md Sections
Maintain these sections in order:
1. **Build & Run Commands** — exact shell commands to build, test, and run the project
2. **Coding Conventions** — language-specific style rules
3. **Architecture Notes** — key design decisions and patterns to follow
4. **Known Workarounds** — error fixes and environment-specific patches
5. **Out-of-Scope** — items not to implement in automated phases

When adding new content, place it in the most specific applicable section.
Never add a new top-level section without flagging it to the human first.

### ADR Template (docs/decision-records/<task-id>-adr.md)

```markdown
# ADR: <Title>

**Date:** YYYY-MM-DD
**Task ID:** <task-id>
**Status:** Accepted

## Context
<Problem statement and constraints that led to this decision>

## Decision
<What was decided and the primary rationale>

## Alternatives Considered
| Option | Pros | Cons |
|--------|------|------|
| ...    | ...  | ...  |

## Consequences
- Positive: ...
- Negative: ...
- Risks: ...
```

### Incident Log Template (docs/incident-logs/<task-id>-log.md)

```markdown

**Date:** YYYY-MM-DD
**Phases affected:** Phase 5, Phase 6

## Implementation Difficulties

### Issue 1

- **Root cause:** ...
- **Workaround applied:** ...
- **Permanent fix needed:** yes / no

## Lessons Learned
1. ...
2. ...

## Corrective Actions for Future Tasks
- [ ] ...
```

## Git Commit Message Types

| Type     | When to use |
|----------|-------------|
| `feat`   | New feature or behaviour |
| `fix`    | Bug fix |
| `refactor` | Code change with no behaviour change |
| `test`   | Adding or modifying tests only |
| `docs`   | Documentation only |
| `chore`  | Build scripts, CI, config changes |
| `perf`   | Performance improvement |

## Duplicate Detection Checklist

Before writing to any documentation file, check:

1. Does CLAUDE.md already have a rule covering this?
   ```bash
   grep -i "<keyword>" CLAUDE.md
   ```
2. Does README.md already document this behaviour?
   ```bash
   grep -i "<keyword>" README.md
   ```
3. Is there an existing ADR covering the same architectural decision?
   ```bash
   ls docs/decision-records/ | xargs grep -l "<keyword>"
   ```

If a match is found, present both the existing and new content to the human and
ask which takes precedence. Document the resolution in the incident log.
